# Contributing to SFP (Skills for Productivity)

Thank you for your interest in contributing to **SFP**! We welcome contributions, whether you are suggesting new skill sources, fixing bugs in the MCP server or skill hive, writing documentation, or improving editor extensions.

---

## Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). Please treat all contributors with respect and courtesy.

---

## How Can I Contribute?

### 1. Reporting Bugs and Suggesting Features
- Before filing an issue, check the existing [Issues](https://github.com/siddu1004/SFP/issues) to see if it has already been reported.
- Use our [Issue Templates](.github/ISSUE_TEMPLATE/) to submit structured, actionable bug reports or feature proposals.
- Include reproduction steps, environment details (OS, Python version, IDE / agent used), and relevant error outputs.

### 2. Adding or Modifying Skill Sources & Categories
SFP collects agent skills from upstream repositories into categories that any agent IDE can install.

- **Sources configuration**: Edit `sources.json` to define which upstream repositories to pull from, target folders, install profiles, and default categories.
- **Categories configuration**: Edit `categories.json` to assign skills to appropriate categories (`names` first, then `patterns`, then source defaults).
- **Naming Constraints**: Category and plugin names **must not** start with `claude-` or `anthropic-` (reserved by Claude Code).
- **Licensing**: Always preserve upstream source licenses. The sync script automatically copies them into `plugins/<category>/LICENSES/`.
- **Public Repositories Only**: SFP is a public repository. Never add content from private or proprietary repositories.

> [!IMPORTANT]
> **Never manually edit generated files!**
> The following files are automatically generated by the sync script:
> - `catalog.json`
> - `index.json` (search index)
> - `SKILLS.md`
> - `plugins/` contents
> - `.agents/plugins/marketplace.json`
> - `.cursor-plugin/marketplace.json`
> - `.claude-plugin/marketplace.json`
> - `gemini-extension.json`
> 
> Whenever you modify `sources.json`, `categories.json`, or templates, always run:
> ```bash
> python3 scripts/sync.py
> ```

## Development & Testing Workflow

### Prerequisites
- Python 3.10+ (Standard Library used extensively)
- Git
- Node.js & npm (if working on `extensions/antigravity-hive/`)

### Running the Test Suite
Before opening a pull request, verify that all test suites pass.

1. **Unit tests for MCP Server and Core Engine:**
   ```bash
   python3 -m unittest discover -s tests
   ```

2. **Speed & Search Index Freshness:**
   ```bash
   python3 -m unittest tests/test_speed.py
   ```
   *(Note: This test ensures `index.json` matches `catalog.json` and is not stale).*

3. **Antigravity Extension Tests (if applicable):**
   ```bash
   cd extensions/antigravity-hive
   npm install
   npm test
   ```

4. **Plugin Validation (if Claude CLI installed):**
   ```bash
   claude plugin validate .
   ```

## Submitting Pull Requests

1. **Fork the repository** and clone your fork locally.
2. **Create a branch** for your work:
   ```bash
   git checkout -b feature/my-feature-name
   ```
3. **Commit your changes**:
   - Write clear, concise commit messages following standard conventions.
   - Do not commit unstaged or unrelated files.
4. **Push to your fork** and open a Pull Request against `main`.
5. **Fill out the Pull Request Template**:
   - Describe the changes clearly.
   - Confirm that tests pass and generated files were regenerated via `python3 scripts/sync.py`.
