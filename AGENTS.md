# Working on SFP

SFP (Skills for Productivity) collects agent skills from other repos into categories any agent IDE can install.

- `sources.json` says which repos to pull from, which skill folders, each source's default category, the externally installed plugins and the install profiles.
- The sync also writes the plugin files for other IDEs from the same categories: `plugins/<cat>/plugin.json` (Cursor, Copilot CLI), `plugins/<cat>/.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json` (Codex), `.cursor-plugin/marketplace.json` and `gemini-extension.json` (Gemini CLI, serves the MCP server). Do not edit them by hand.
- `categories.json` says what the categories are and which category each skill goes in (`names` first, then `patterns`, then the source's default).
- `plugins/`, `catalog.json`, `index.json` (the saved search index), `SKILLS.md` and `.claude-plugin/marketplace.json` are generated by `python3 scripts/sync.py`. Never edit them by hand. `tests/test_speed.py` fails if `index.json` is stale: run the sync.
- `templates/sfp/` is the router skill; the sync adds its generated `reference/index.md`. `templates/public-apis/` wraps the public-apis list and its search script.
- `scripts/install.py` installs into each tool's skills folder. Tool paths live in its `TOOLS` table. `install.py mcp` registers the MCP server in each IDE's settings.
- `mcp/sfp_mcp.py` is the MCP server (stdio, Python standard library only; `select_skills` and `give_feedback` write only the hive's own logs in `~/.sfp`). It reads `catalog.json` and the skill files, so run `python3 scripts/sync.py` first. Run `python3 -m unittest discover -s tests` after changing it; the tests drive it with real JSON-RPC.
- `mcp/sfp_hive.py` is the skill hive, the engine behind the `sfp-hive` skill (`templates/sfp-hive/`) and the `select_skills` and `predict_next` MCP tools: five signals (words, project files, phase of work, category, history), an agreement rule, overlap suppression and role allocation. `mcp/sfp_learn.py` is the feedback loop: it logs each decision, takes feedback (`give_feedback`: helped, unhelpful, ignored, missing) and fits a small model of which task words go with which skills, which `select` applies. Data goes to `~/.sfp` (`decisions.jsonl`, `feedback.jsonl`). `python3 mcp/sfp_hive.py evaluate` and `learning-curve` score them on `tests/search_*.json`, `tests/stack_eval.json` and `tests/hive_heldout.json`; `tests/test_hive.py` and `tests/test_learn.py` hold the floors. Do not tune on `hive_heldout.json`: it is the held-out set. `docs/HIVE.md` explains the design and what failed on the way.
- `mcp/sfp_stack.py` is the earlier stack engine (v1). The hive reuses its vocabulary, project fingerprint, recipes and usage-log reader, and `--engine v1` still runs it. Its recipes live in `mcp/stack_recipes.json`. `tests/test_stack.py` holds its floors. `docs/PRODUCT.md` is the product analysis.
- `templates/career/` is the career-ops launcher (a skill plus `scripts/setup.py` and `patches/data-root.patch`). The sync fills in the pinned commit and fails if the patch no longer applies to the upstream commit it integrates; if that happens, rebase the patch.
- `docs/INTEGRATION.md` is the hand-written guide to installing SFP together with ECC and OmniRoute. Its commands come from those projects' READMEs, so recheck them when `sources.lock.json` moves to a new ECC or OmniRoute release.
- `apps/apps.json` lists the programs some skills only guide (OmniRoute, Strix, claude-mem...): requirements, how to detect, install, update, start, health URL. `apps/sfp_app.py` is the stdlib engine. The sync copies the engine and the program's entry into every skill whose source (`sources`) or name (`names`) matches, adds a note after its frontmatter, and sets `app` in the catalog. Recheck the commands when `sources.lock.json` moves. `tests/test_apps.py` holds the floors.
- `extensions/antigravity-hive/` is a TypeScript VS Code extension (Antigravity and other forks) that runs `mcp/sfp_hive.py` and shows the result. `src/hive.ts` has no editor code and is unit tested; `src/extension.ts` is the glue, tested against a stand-in `vscode` module. `npm test` in that folder runs 46 tests; `tests/test_extension.py` checks the manifest from Python. `docs/ANTIGRAVITY.md` explains it and holds the implementation prompts. It does not modify Antigravity, and the hive's JSON shape (`stack`, `layers`, `decision`, and with `--explain` the `explain` list) is its contract: change both together. `select` also takes `--include` and `--exclude` (the user's pins and removals); `docs/HIVE-INSPECTOR.md` is the brief for the interface built on them.
- `mcp/sfp_track.py` follows the agent: workspace events become evidence per phase, one Kalman filter per phase smooths it, and a Markov chain over phase changes predicts the next phase; `sfp_hive.py track` reads events and passes the phase to `select` as `phase_hint`. State is `track_state.json` and `phases.json` in the data folder. `tests/track_sessions.json` is its dev set and `tests/track_heldout.json` its held-out set (do not tune on it); `tests/test_track.py` holds the floors; `docs/TRACKING.md` has the numbers. `clusters.json` groups the skills into named clusters, read by `mcp/sfp_clusters.py` (`sfp_hive.py clusters`, `cluster-add`, `cluster-remove`); `tests/test_clusters.py` checks every skill has one home. `docs/HIVE-STUDIO.md` is the brief for the single extension built on all of this.
- `purposes.json` (15 purposes: what a skill is for), `bundles.json` (named, ordered skill sets; recipes by reference) and `mcp/sfp_library.py` (assigns purposes, lists bundles, builds the `library` payload) make up the skill library; `sfp_hive.py library`, `bundles`, `bundle-add`, `bundle-remove` and `select --bundle` expose it. `tests/purpose_labels.json` is the dev set for purposes (the rules were tuned on it) and `tests/purpose_heldout.json` the held-out one (do not tune on it); `tests/test_library.py` holds the floors. The editor searches the payload in `extensions/antigravity-hive/src/library.ts`, whose tokenizer must stay the same as `core.tokens` in `mcp/sfp_mcp.py` (a parity test checks). `docs/LIBRARY.md` has the numbers; `docs/LIBRARY-BRIEF.md` is the brief for the sidebar interface.
- `mcp/sfp_live.py` (`sfp_hive.py live`) attaches skills to a message while it is typed: waits for words, stays steady, keeps the user's pins and removals, logs only on `--commit`; `extensions/antigravity-hive/src/live.ts` debounces it. `tests/test_live.py` and `test/live.test.js` hold the floors (the extension now runs 46 tests); `docs/LIVE.md` has the rules and the brief for wiring it.
- `capabilities.json` and `mcp/sfp_needs.py` find what a task needs that the model cannot do alone (3D, the web, limits, free APIs, media, a browser, memory, pentests): the provider skill joins the stack, the rest are preloaded, and `--check` says which program or key is missing and the command to fix it. `select`, `live` and the MCP `select_skills` use it (`--no-needs` turns it off). `tests/needs_dev.json`, `tests/needs_heldout.json` and `tests/test_needs.py` hold the floors; `docs/NEEDS.md` has the numbers and the brief.
- `mcp/sfp_route.py` is the local model router (stdlib, OpenAI chat API on 127.0.0.1): it finds local models (Ollama, LM Studio, llama.cpp, Jan, vLLM), sizes each request, orders models by policy, and fails over on limits and errors; keys are named by environment variable and never stored. `tests/test_route.py` runs it against fake servers; `docs/ROUTER.md` has the design, its limits and the brief for the sidebar. The `never-run-out` need points to it first.
- `archive/fork-patches/` holds patches for work that only the author's forks had. Nothing in SFP depends on them.
- Category and plugin names must not start with `claude-` or `anthropic-`: Claude Code reserves them.
- Keep each source's license: the sync copies it into `plugins/<category>/LICENSES/`.
- The repo is public. Do not add content from private repos.

After changing sources or categories: run the sync, then `claude plugin validate .`.

## SFP Live Hive Chat Protocol
Whenever responding to the user in the Antigravity IDE agentic chat:
1. Run SFP Hive skill selection for the user's task prompt.
2. Render the active skills banner with prompt delta (`+ Added`, `- Removed`), three-tier layer allocation (`⚡ Base`, `🛡️ Check`, `✨ Finish`), and token budget.
3. Actively follow and execute the guidance of the selected skills.
