# Working on SFP

SFP (Skills for Productivity) collects agent skills from other repos into categories any agent IDE can install.

- `sources.json` says which repos to pull from, which skill folders, each source's default category, the externally installed plugins and the install profiles.
- `categories.json` says what the categories are and which category each skill goes in (`names` first, then `patterns`, then the source's default).
- `plugins/`, `catalog.json`, `index.json` (the saved search index), `SKILLS.md` and `.claude-plugin/marketplace.json` are generated by `python3 scripts/sync.py`. Never edit them by hand. `tests/test_speed.py` fails if `index.json` is stale: run the sync.
- `templates/sfp/` is the router skill; the sync adds its generated `reference/index.md`. `templates/public-apis/` wraps the public-apis list and its search script.
- `scripts/install.py` installs into each tool's skills folder. Tool paths live in its `TOOLS` table. `install.py mcp` registers the MCP server in each IDE's settings.
- `mcp/sfp_mcp.py` is the MCP server (stdio, Python standard library only; read-only except `record_usage`, which appends to the local usage log). It reads `catalog.json` and the skill files, so run `python3 scripts/sync.py` first. Run `python3 -m unittest discover -s tests` after changing it; the tests drive it with real JSON-RPC.
- `mcp/sfp_hive.py` is the hive, the engine `sfp-manager` and the `recommend_stack` and `predict_next` MCP tools use since 2.0.0: scouts and quorum, stop signals, response thresholds and evaporating pheromone trails, built on `sfp_stack.py` (v1). `python3 mcp/sfp_hive.py evaluate` scores it against v1 and plain search on `tests/search_*.json`, `tests/stack_eval.json` and `tests/hive_fresh.json`; `tests/test_hive.py` holds the floors. Do not tune on `hive_fresh.json`: it is the held-out set. `docs/HIVE.md` explains the design.
- `mcp/sfp_stack.py` is the v1 stack engine. The hive reuses its vocabulary, project fingerprint, scoring, recipes and usage log, and `record_usage` writes through it. It picks a few skills per task from the task words, the project's files, the phase of work and a Markov chain over skill sequences. Its recipes live in `mcp/stack_recipes.json`. `python3 mcp/sfp_stack.py evaluate` scores it on its own; `tests/test_stack.py` holds its floors. `docs/MANAGER.md` explains it.
- `templates/career/` is the career-ops launcher (a skill plus `scripts/setup.py` and `patches/data-root.patch`). The sync fills in the pinned commit and fails if the patch no longer applies to the upstream commit it integrates; if that happens, rebase the patch.
- `docs/INTEGRATION.md` is the hand-written guide to installing SFP together with ECC and OmniRoute. Its commands come from those projects' READMEs, so recheck them when `sources.lock.json` moves to a new ECC or OmniRoute release.
- `archive/fork-patches/` holds patches for work that only the author's forks had. Nothing in SFP depends on them.
- Category and plugin names must not start with `claude-` or `anthropic-`: Claude Code reserves them.
- Keep each source's license: the sync copies it into `plugins/<category>/LICENSES/`.
- The repo is public. Do not add content from private repos.

After changing sources or categories: run the sync, then `claude plugin validate .`.
